# 系统综述检索工作流（方法学胶水）

配套 pubmed-mcp 1.4.0 的检索助手工具。本文件是方法学说明，不是工具代码；亦作为 `/systematic-review` skill 随仓库分发（.claude/skills/systematic-review/SKILL.md）。
分工〔本项目自订〕：工具做机械可复现的事；判断由人与 LLM 按预设标准做。工具不声称查全率/查准率。

## 0. 先决条件

- 一个明确的研究问题（PICO：对象/干预/对照/结局），以及事先写好的纳入排除标准。问题不清楚，工具无法判断什么叫漏文献。
- 一批已知相关文献的 PMID（金标准集，建议 10–30 篇〔自订建议规模〕），**来自多个来源**（已有综述、专家推荐、手工查找），不要只取某一篇综述的参考文献——那会偏向它的检索式（循环偏倚）。
- 设 `PUBMED_AUDIT_DIR` 开启检索留痕（可选但强烈建议），供最后写检索报告。

## 1. 拆概念、查词

1. 把研究问题拆成 2–4 个核心概念。不是所有纳入标准都进检索式：有些条件适合后续人工筛选，过早限定会漏文献。
2. 对每个概念用 `mesh(概念词)` 查官方主题词，读入口词（同义词）、树号、下位词、范围注。
   - 下位词决定是否展开（explode）：例如 Tooth Resorption 的下位词 Root Resorption〔实测〕，正畸牙根吸收综述通常两者都要。
   - 同时读上位词、历史前身词（previous indexing）与引入年份；历史词是扩展线索，不能单凭年份断定某篇文章的漏检原因。
   - MeSH 覆盖不全：新材料/新术式可能无描述符，用标题/摘要同义词补。
3. 为每个概念收集同义词、拼写变体、截词（resorption*）。LLM 想的词要核对，mesh 给的词以查询时点 NCBI 返回为准。

## 2. 组检索式

- 同一概念的同义词用 `OR`，不同概念用 `AND`；布尔算子大写，引号只包短语，括号配对。
- 字段：主题词 `[MeSH Terms]` + 标题摘要 `[tiab]` 双轨，减少漏检。
- 先不加研究类型/语言等过滤器，看基础命中数；过滤器后续按需加并记录。
- 用 `count(式子)` 看命中数与实际执行式（querytranslation）。**先读 ⚠️**：改写后的计数不是原式计数。

## 3. 验已知集（查全的核心检查）

1. `check_recall(式子, 金标准PMID)` → found/missing。
2. 先读 `term_ignored`、`term_degraded`、全部批次的 `querytranslations` 与警告；发现失真先修查询。再对 missing（state=present）逐块调用 `count("某概念OR块 AND pmid[uid]")`，核对执行式和标引后判断原因。
   - 【已作废，修订日期：2026-11-12】旧句“哪个块返回零，就是哪个概念的词没写够”把单次未匹配直接归因于缺词；也可能是字段、标引、语法或限制条件。
3. 补词、改式，重跑 check_recall，直到已知集尽量找回。
4. **诚实边界**：已知集找回只证明这批文献被检回，不代表整体查全率；金标准集本身可能有偏。missing 里 unavailable/unknown 的号存在性未确认，不能断定是式子漏了它。若返回 `term_ignored=true`（常见于中文词被 NCBI 忽略），found 是假阳性、不代表式子匹配——换英文词重跑。

## 4. 迭代对比（防越改越漏）

- 每次改式用 `diff(旧式, 新式)` 看新增/丢失。丢失的已知相关文献要查原因。
- 命中更多不等于更好；集合差不判断相关性。
- 查准估计：按预设纳入标准对结果抽样人工/LLM 筛选，统计相关比例（工具不替你做这个判断）。

## 5. 取全导出

- 定稿后 `export(式子, 路径, format)`：
  - `pmids`：纯 PMID 列表；`csv`：核心题录，**不含摘要**；`medline`：.nbib，保留来源中已有的摘要与主题词，不保证每条都有。摘要也可用 `fetch_abstracts` 单独获取。
  - 【已作废，修订日期：2026-11-12】旧句“CSV 含摘要筛选所需字段”容易被误解为含摘要；源码 `_export_csv` 没有导出摘要字段。
  - 路径必须尚不存在；并发调用使用独立临时文件，安全发布失败时报错。
  - 超 9999 自动按发表日期切片；切片计数和可能大于总数（记录带多个发表日期），去重后与总数核对，警告如实说明〔实测〕。
  - 筛选工具导入兼容性以对方文档为准⚠️【待确认】；不保证与 PubMed 网页导出逐字一致。
- 记录导出时点；数据库会更新，结果以导出时点为准。

引文补查可用 `links(pmids, to="refs")` 看参考文献、`to="citedin"` 看施引文献；`to="pubmed"` 仍是相关文献。默认文本会标展示截断，`out_path` 保存本次全量来源关系；仅覆盖 PubMed 已录入关系，缺关联不证明无引文。

更新检索可用 `datetype="edat"` 配显式日期，再以 `--diff-files` 比较新旧完整名单，`--export-pmids` 导出新增题录。`--snowball` 保存单轮引用候选及可复算材料；`--checkpoint-dir` / `--resume-export` 只恢复已持久化名单后的题录阶段。详见 [补检与文件工作流](retrieval-files.md)。

## 6. 写检索报告（PRISMA-S）

- 读取 `PUBMED_AUDIT_DIR` 下的实际日志文件，用 `--audit-report <日志...> --out <报告.md或.csv>` 整理数据库、平台、检索时间、原始式、执行式、计数与警告。新日志为 `searches-<pid>-<session>.jsonl`，旧 `searches.jsonl` 仍可输入；旧版固定文件名说明已作废〔本次实现订正〕。缺失字段写待确认，不能把多次试检命中数相加当纳入数。详见 [记账与报告](audit-report.md)。
- 具体报告条目以 PRISMA-S 原文为准⚠️【待确认，未逐字核对】；本工作流不声称覆盖其全部条目。
- 多库检索：PubMed 单库不等于系统综述全部检索。是否补 Embase/Cochrane/试验注册/引文追踪由研究问题定；本工具目前只覆盖 PubMed。

## 交付入口与验收

策略及范围确认后，使用 [综述检索交付](review-delivery.md) 的方案模板和命令生成交付目录。完整名单、同源题录摘要、待筛选表、RIS、日志与问题清单一起交付；技术完成与方法学待确认分别报告。不要把“工具能调用”当成“研究检索已完成”。

## 7. 筛选与写作（工具之外）

- 筛选：LLM 按预设标准读题录/摘要辅助判断，人复核；摘要信息不足标待确认，不擅自排除。
- 提取表/PRISMA 流程图/稿件：LLM + docx/xlsx 等文档技能；MCP 提供结构化题录与留痕数字。
- PDF 下载走单独的 download-literature 流程，不在本工具内。
