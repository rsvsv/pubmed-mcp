# 系统综述检索工作流（方法学胶水）

配套 pubmed-mcp 1.4.0 的检索助手工具。本文件是方法学说明，不是工具代码；亦作为 `/systematic-review` skill 随仓库分发（.claude/skills/systematic-review/SKILL.md）。
分工〔本项目自订〕：工具做机械可复现的事；判断由人与 LLM 按预设标准做。工具不声称查全率/查准率。

## 0. 先决条件

- 明确研究问题与预设纳排标准。按问题选框架：干预可用 PICO，暴露可用 PECO，诊断写清目标人群、待评价检测及参考标准，范围综述可用 PCC；框架要素不必全部进入检索式。
- 尽可能收集多来源的独立已知相关文献，记录 PMID 与来源，不把当前检索结果倒充验证集。缺少时可先拟草案和试检，明确未完成独立验证；交付入口中的方法学待确认状态仍须如实保留，缺独立已知集时成果只算草案，保持 `needs_methodology_review`，不能声称查全、已批准或完成综述。
- 【已作废，修订日期：2026-11-15〔本次修订记录〕】旧“金标准集建议 10–30 篇、固定 PICO、拆成 2–4 个核心概念”均属本项目自订口径，不是外部方法学硬门槛。作废理由：固定规模和框架不适用所有问题；替代为按范围说明验证覆盖和检索概念选择。
- 设 `PUBMED_AUDIT_DIR` 开启检索留痕（可选但强烈建议），供最后写检索报告。

## 1. 拆概念、查词

1. 选择有区分力且可检索的核心概念。不是所有纳入标准都进检索式：有些条件适合后续人工筛选，过早限定会漏文献。
2. 对拟采用的主题词用 `mesh(概念词)` 核实，读入口词、树号、下位词、范围注；复用同一概念已核实的结果，不对每个同义词重复查词。
   - 下位词决定是否展开（explode）：例如 Tooth Resorption 的下位词 Root Resorption〔实测〕，正畸牙根吸收综述通常两者都要。
   - 同时读上位词、历史前身词（previous indexing）与引入年份；历史词是扩展线索，不能单凭年份断定某篇文章的漏检原因。
   - MeSH 覆盖不全：新材料/新术式可能无描述符，用标题/摘要同义词补。
3. 为每个概念收集同义词、英美拼写变体（randomised/randomized、paediatric/pediatric、programme/program）、词形与截词（resorption*）。缩写逐个按摘要里的展开核对；同一缩写可有不同含义，缩写共现或首屏命中不足以纳入。LLM 想的词要核对，mesh 给的词以查询时点 NCBI 返回为准。
4. 要纳入量表／问卷／评分工具的原始开发研究时，用题名关键词＋作者（`[au]`）定位，补 development／validation／original 等词，读 `full` 题录或摘要确认版本。首屏排序、综述引用或衍生版不能证明是原始版本；未定位就写未定位。
5. 引号内截词是否实际扩展〔未核实〕，不把「引号会／不会扩展」当定论。需要判断时做词形确定性对照：对已知单词、复数／变体与完整短语分别取回并核对各自 PMID／标题（不能只看 count），一次只改一个因素；计数差本身不证明扩展机制。

## 2. 组检索式

- 同一概念的同义词用 `OR`，不同概念用 `AND`；布尔算子大写，引号只包短语，括号配对。
- 字段：主题词 `[MeSH Terms]` + 标题摘要 `[tiab]` 双轨，减少漏检。
- 先不加研究类型/语言等过滤器，看基础命中数；过滤器后续按需加并记录。
- 需要题录就用 `search(式子)` 同时看计数、执行式与题名；只需数量才用 count。**先读 ⚠️**：改写后的计数不是原式计数。相关性排序、日期排序与差集预览均不是随机样本，不能用于直接估计查准。

日期两种口径：`pdat`（发表日期）与 `edat`（入库日期）的区间都含首尾，以执行式回显的实际起止为准。同一字段、同一区间的重复条件只是重复，不会变窄；把 `pdat` 与 `edat` 的同日历窗口叠加（同日历边界也不等价），或叠加不等价日期限制，才会取交集把窗口变窄。不要双加，写明实际字段与窗口。跨年在线出版并列卷期年与 Epub；年份对不上或只知其一时标未核，不按显示年份手删。

## 3. 验已知集（查全的核心检查）

1. `check_recall(式子, 金标准PMID)` → found/missing。
2. 先读 `term_ignored`、`term_degraded`、全部批次的 `querytranslations` 与警告；发现失真先修查询。再对 missing（state=present）逐块调用 `count("某概念OR块 AND pmid[uid]")`，核对执行式和标引后判断原因。`state=present` 只说明记录存在、本次执行式未取回，不指出原因；诊断时一次只改一项限制（日期／字段／概念块），其余不变并记录改动项，对照结果只支持「在该项下找回」，不能替用户归因到其原式或屏幕范围。
   - 【已作废，修订日期：2026-11-12】旧句“哪个块返回零，就是哪个概念的词没写够”把单次未匹配直接归因于缺词；也可能是字段、标引、语法或限制条件。
3. 补词、改式，重跑 check_recall，直到已知集尽量找回。
4. **诚实边界**：已知集找回只证明这批文献被检回，不代表整体查全率；金标准集本身可能有偏。missing 里 unavailable/unknown 的号存在性未确认，不能断定是式子漏了它。`term_ignored`／`term_degraded` 要按 `checks` 分批判定：某批失真时该批实取不代表原式命中，只重跑该批；不能据此宣布其他批次或全部 `found` 都是假阳性（常见于中文词被 NCBI 忽略，换英文词重跑该批）。
   > 【已作废，修订日期：2026-11-19】旧句「若返回 `term_ignored=true`（常见于中文词被 NCBI 忽略），found 是假阳性、不代表式子匹配——换英文词重跑。」作废理由：把单批失真扩大成全部 `found` 无效；结果按 `checks` 分批记录，其他可靠批次的 `found` 仍有效。

## 4. 迭代对比（防越改越漏）

- 记录改式理由、执行式与警告；关键策略变化需要完整集合增减时用 `diff(旧式, 新式)`。丢失的已知相关文献要查原因。max_show 仅限制展示，后台仍取全集；超出 diff 窗口时导出名单后比较文件差集。
- 【已作废，修订日期：2026-11-15〔本次修订记录〕】旧“每次改式必跑 diff”是本项目自订流程，未区分局部语法修正与实质策略变化；替代为按验证问题选择操作，保留关键策略变化的完整增减检查。
- 命中更多不等于更好；集合差不判断相关性。
- 查准估计：按预设纳入标准对结果抽样人工/LLM 筛选，统计相关比例（工具不替你做这个判断）。

## 5. 取全导出

- 定稿后 `export(式子, 路径, format)`：
  - `pmids`：纯 PMID 列表；`csv`：核心题录，**不含摘要**；`medline`：.nbib，保留来源中已有的摘要与主题词，不保证每条都有。摘要也可用 `fetch_abstracts` 单独获取。
  - 【已作废，修订日期：2026-11-12】旧句“CSV 含摘要筛选所需字段”容易被误解为含摘要；源码 `_export_csv` 没有导出摘要字段。
  - 路径必须尚不存在；并发调用使用独立临时文件，安全发布失败时报错。
  - 超 9999 自动按发表日期切片；切片计数和可能大于总数（记录带多个发表日期），去重后与总数核对，警告如实说明〔实测〕。
  - 筛选工具导入兼容性以对方文档为准⚠️【待确认】；不保证与 PubMed 网页导出逐字一致。
- 导出绑定最终式与范围：固定 `term`、`field`、`datetype`、`mindate`／`maxdate`（含首尾）与导出时点，并核对返回的 `effective_query`、`frozen_bounds`、`datetype_applied`、`scope_status`；实际窗口与计划不一致时先修再交；保存原式、字段、窗口与固定名单，供重新比集合。export 没有 `sort` 参数，不要把 `search.sort` 传给它；比较按 PMID 集合，不要求顺序。
- 导出后按固定 `all-pmids.txt` 或独立原名单逐号核对，不只比条数；同条数不证明同集合，也不证明与用户原屏／原式一致。没有原名单或原式时只报告本次范围，不能称逐号相同。
- 缺独立已知集时保持草案／`needs_methodology_review`；即使文件已生成，也不能声称查全、已批准或完成综述，不能把本次命中倒充验证集。
- 记录导出时点；数据库会更新，结果以导出时点为准。

引文补查可用 `links(pmids, to="refs")` 看参考文献、`to="citedin"` 看施引文献；`to="pubmed"` 仍是相关文献。默认文本会标展示截断，`out_path` 保存本次全量来源关系；仅覆盖 PubMed 已录入关系，缺关联不证明无引文。

更新检索可用 `datetype="edat"` 配显式日期，再以 `--diff-files` 比较新旧完整名单，`--export-pmids` 导出新增题录。`--snowball` 保存单轮引用候选及可复算材料；`--checkpoint-dir` / `--resume-export` 只恢复已持久化名单后的题录阶段。详见 [补检与文件工作流](retrieval-files.md)。

## 6. 写检索报告（PRISMA-S）

- 读取 `PUBMED_AUDIT_DIR` 下的实际日志文件，用 `--audit-report <日志...> --out <报告.md或.csv>` 整理数据库、平台、检索时间、原始式、执行式、计数与警告。新日志为 `searches-<pid>-<session>.jsonl`，旧 `searches.jsonl` 仍可输入；旧版固定文件名说明已作废〔本次实现订正〕。缺失字段写待确认，不能把多次试检命中数相加当纳入数。详见 [记账与报告](audit-report.md)。
- 报告大集合时先写命中总数、本次实取、已展示／待看与未完成项，再给名单或分页；整页 JSON 转录易错，名单全不等于题名全。
- 具体报告条目以 PRISMA-S 原文为准⚠️【待确认，未逐字核对】；本工作流不声称覆盖其全部条目。
- 多库检索：PubMed 单库不等于系统综述全部检索。是否补 Embase/Cochrane/试验注册/引文追踪由研究问题定；本工具目前只覆盖 PubMed。

## 交付入口与验收

策略及范围确认后，使用 [综述检索交付](review-delivery.md) 的方案模板和命令生成交付目录。完整名单、同源题录摘要、待筛选表、RIS、日志与问题清单一起交付；技术完成与方法学待确认分别报告。不要把“工具能调用”当成“研究检索已完成”。

## 7. 筛选与写作（工具之外）

- 筛选：LLM 按预设标准读题录/摘要辅助判断，人复核；摘要信息不足标待确认，不擅自排除。
- 提取表/PRISMA 流程图/稿件：LLM + docx/xlsx 等文档技能；MCP 提供结构化题录与留痕数字。
- PDF 下载走单独的 download-literature 流程，不在本工具内。
