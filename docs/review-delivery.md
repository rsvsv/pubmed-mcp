# 综述检索交付：什么时候算完成

本入口把既有检索工具串成可检查的 PubMed 候选文献交付目录。交付对象是可开始人工筛选的材料，不是已经完成的系统综述。状态规则属于本项目自订验收口径。

## 给助手的输入

提供研究问题、纳入排除标准和已有相关文献；助手负责查词、拟式、核对实际执行式和迭代。未确定的学术范围保留为待确认，不由程序代替研究者批准。

助手将确定的信息写成方案 JSON，字段见 `review-plan.template.json`。`term` 是英文 PubMed 检索式；`strategy_status` 初始为 `draft`。只有确有研究者批准或既有批准依据时，才填写 `approved` 与 `strategy_review_note`。来源明确的已知文献放在 `known_relevant`；不能从本次命中中挑几篇倒充独立验证集。

日期限制同时给出 `mindate`、`maxdate`；不限制时都留空。`other_databases` 与 `citation_tracking` 记录范围决策或实际工作指针，文字记录不证明已完成外部数据库检索。

## 执行入口

以下均为本项目自订命令；示例文件名为占位路径。先保存方案，输出目录必须不存在。

```bash
pubmed-review --review-plan review-plan.json --out-dir review-run
```

源码或本机文件安装也可用主入口：

```bash
python -I pubmed_mcp.py --review-plan review-plan.json --out-dir review-run
```

程序在独立进程内自动开启该任务的留痕，先固定完整 PMID 名单，再分批抓取题录；摘要筛选表与 RIS 由同一份题录生成。无需手工拼接各工具产物。

网络中断后：

```bash
pubmed-review --resume-review review-run
```

已提交且哈希一致的阶段复用。未完成任务的方案或实现变化时拒绝混用，需新建任务。普通任务的阶段文件已经发布、但阶段状态未提交时保守拒绝覆盖，保留目录并新建任务。`.review.lock` 文件会保留，互斥由操作系统文件锁执行；进程退出自动释放锁，恢复无需手动删除。正在运行的任务不允许并发恢复。

若已有 `delivery.json` 但仍缺题录，恢复入口先核验原交付，再在相邻的 `review-run.repair` 目录补抓。原交付完整快照保存在修复目录的 `original/`，固定名单和已取回题录保持不变，只请求缺失项；命令返回的 `directory` 指明实际交付位置。原目录不被覆盖。修复目录中未提交的程序产物归档到 `uncommitted/` 后重试，包括创建后未写入表头的空筛选文件；含人工筛选判断的表格拒绝移动或覆盖。

日志存在截断或坏行时，原始字节保留，报告列出 `INVALID_INPUT` 及来源。其余已提交阶段的目标审计事件仍必须完整、唯一且摘要匹配；找不到、重复或改变的目标事件不能复用。损坏日志及原交付已有审计缺口继续阻止 `ready_for_screening`，补齐题录不代表补齐历史证据。

交付核验：

```bash
pubmed-review --verify-review review-run
```

核验从方案与固定名单推导必需阶段，再检查文件哈希、审计事件、阶段回执与实际内容的对应关系，以及题录批次、筛选行、RIS、报告与汇总状态。删除必需阶段后重新计算清单哈希也不能通过。完整交付目录整体移动后仍能核验。哈希没有数字签名，只证明与清单一致，不能证明来源真实或检索查全。

## 收到什么

| 文件 | 用途 |
|---|---|
| HANDOFF.md | 首先阅读：交付状态、未解决事项、责任边界 |
| plan.json | 研究问题、标准、最终检索式、日期及范围决策 |
| all-pmids.txt | 本次完整去重 PMID 基线，供补检比较 |
| search-result.json 与伴随说明 | NCBI 实际执行式、计数、警告与文件绑定 |
| records/ | 本次题录与结构化摘要快照，保留缺失 PMID 与抓取时间 |
| screening.csv | 每个候选均保留一行；含摘要、来源位置、待筛选决策及排除原因栏 |
| references.ris | 同一题录快照生成的导入材料；导入兼容性须在目标软件核对 |
| recall/ | 已知文献找回结果；缺已知集时不伪造该目录里的证据 |
| audit/ 与 search-log.csv | 本次实际请求记录和便于阅读的检索过程表 |
| state.json | 已提交阶段及哈希，用于续跑 |
| delivery.json | 交付清单、计数、待办与文件哈希 |

原始 screening.csv 用于交付核验；另存工作副本进行筛选。不因缺摘要或题录失败自动排除候选。题录中的数值仅是 PubMed 来源记录，写入论文前仍要核对原文位置。

## 完成状态

- `ready_for_screening`：本次检查未发现执行差异，策略已有批准记录、已知集检查未见遗漏或失真、范围决策有记录。仅表示 PubMed 候选材料可进入人工筛选，不表示方法学经独立专家认证。
- `needs_methodology_review`：材料已生成，但策略尚未批准、缺少独立已知集、存在查询警告或范围决策待确认。助手应指出具体待办，不能把它说成“综述检索已经完成”。
- `needs_execution_repair`：题录缺失、计数差异或留痕不完整。已有材料保留，执行缺口仍由助手处理。
- 没有 `delivery.json`：尚未完成交付，不能把目录里已有文件当完整结果。

零命中必须复核；已知集找回不等于总体查全率；PubMed 单库不等于全部系统综述检索；来源没有摘要不证明文章没有可用内容。引用补查与其它数据库仍按研究方案另行执行，不能把方案中的一句话当执行证据。

程序负责检索执行、完整名单、题录与可追溯材料。助手负责解释警告、修复执行缺口、准备可审核检索策略和交付说明。研究者负责策略及范围批准、纳入排除、全文事实核对和学术结论。
