# 导出核对字段（未发布补丁）

`export(as_json=True)` 及已启用的 `export` 审计留痕新增以下字段，已有字段含义保留。普通文本输出保留原形状，只有零记录 CSV 的提示改为“仅含表头”。本补丁没有实现侧车文件、更新检索或提速方案。

| 字段 | 本项目自订口径 |
|---|---|
| `written_records` | 实际写入的记录/数据行数，不含 CSV 表头。pmids 按 PMID 行计；CSV 包括缺元数据的占位行；RIS/MEDLINE 按实际题录计。 |
| `missing_pmids` | 已检回 PMID 中，题录或元数据缺失/不可用的完整名单，不受文本警告的展示截断影响。CSV 中这些号仍有占位行。pmids 格式不取题录，此字段为空不证明元数据可用。 |
| `integrity_status` | `missing_records`：已发现题录/元数据缺失；否则有计数或分页问题为 `needs_review`；否则为 `no_discrepancy_detected`。最后一种仅表示核对未发现异常，不证明查全。 |
| `integrity_issues` | 全部触发原因，允许同时出现；不使用互斥状态隐藏其他问题。 |

原因取值：

- `missing_records`：存在缺失/不可用题录或元数据。
- `id_count_mismatch`：唯一 PMID 数与起始命中数不同。不能仅凭差额知道缺了哪些号，因此不会编造 `missing_pmids`。
- `count_changed`：结束命中数与起始命中数不同。
- `pagination_drift`：分页过程中出现重复或计数不一致提示。
- `slice_overlap_or_count_mismatch`：跨片重复或切片计数和不一致。多发表日期也可能造成正常重叠，需要复核，不能直接认定缺失。

`unique` 仍指检回的唯一 PMID 数，不能用作实际题录数。遇到异常仍按原契约交付文件并报告警告；不自动删除部分结果、不把计数一致表述为完整性保证。

请求计数上下文使用 token 在 `finally` 中恢复，覆盖成功、异常和取消；恢复调用前的上下文而非一律清空，避免破坏嵌套调用方。

回归入口：`tests/test_export_integrity.py`。测试使用本项目自订夹具，验证字段与实际输出文件相符、CSV 占位语义、完整缺失名单、计数变化、跨片重叠及上下文恢复；不能替代 NCBI 联网验收。

本补丁最终验收：新增回归 11 条，全套 182 条在 Python 3.13.14 / mcp 1.29.0 和 Python 3.10.20 / mcp 2.3.0 均通过〔本轮工具输出实测〕。两代 SDK 的 `call_tool` 导出成功路径也通过模拟响应验证〔本轮工具输出实测〕。审查后追加跨格式的缺失名单截断、计数变化与审计一致性组合测试；此前新增 10 条、全套 181 条属于本轮中间验收时点〔本轮工具输出实测〕。本轮没有进行联网验收或已安装服务的 stdio 验收，没有覆盖安装副本。
